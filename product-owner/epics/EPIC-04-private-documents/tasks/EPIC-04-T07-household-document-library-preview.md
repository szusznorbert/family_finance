# EPIC-04-T07: Household document library and private preview

## Goal and user value

A member can find and open the current household's private documents on a phone after upload. They can preview JPEG/PNG images and safely download or open PDFs in the browser.

## Scope and non-goals

- Provide a paginated, newest-first list of the current household's `AVAILABLE` documents, with only display metadata. `OWNER`, `MEMBER`, and `VIEWER` can read. Recheck the current session and household membership for every list/content request.
- Provide a mobile-oriented document list accessible from the home page and T06 upload success state. Fetch JPEG/PNG previews only when selected, through the existing authorized private-content route. PDFs and unsupported image formats use the existing safe download path.
- No public or long-lived file URL, storage key, hash, local file path, deletion, OCR, automatic receipt processing, or ledger entry. Do not download the full document collection to render the list.

## T07 image-preview decoding limits

**Risk and goal:** the 500 KiB client-compression target does not limit the pixel dimensions of compressed JPEG/PNG; decoding an extreme-dimension file in a browser can allocate substantial memory. On upload, the server should inspect image dimensions without decoding and clearly reject oversized preview images with `IMAGE_DIMENSIONS_TOO_LARGE`.

**Scope and files:** `apps/api/src/lib/document-upload.ts` reads JPEG SOF and PNG IHDR dimensions from a bounded header prefix and validates them without bitmap decoding; `apps/api/src/app/api/v1/households/[householdId]/documents/route.ts` maps the specific error to a clear client error. Technical ceiling: at most 12,000 pixels on either axis and 24,000,000 total pixels. PDF and attachment-only HEIC/HEIF paths remain unchanged. The web 500 KiB compression target is unchanged.

**Acceptance and verification:** JPEG/PNG below the ceiling still returns `201`; images above either axis or total-pixel limit, even below 500 KiB, receive a clear rejection; missing/truncated dimension headers are rejected; PDF/HEIC/HEIF detection remains unchanged. No full-image decode, secondary file buffer, or unbounded header collection. Node 24 API typecheck, lint on affected files, diff-check, and manual parser/API check with synthetic bytes.

**Open item:** the 12,000 px / 24 MP ceiling is a provisional safety limit; T07 preview QA on a real mobile device has not yet occurred.
